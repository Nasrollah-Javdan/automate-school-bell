# DS School Bell — زنگ مدرسه DS

نرم‌افزار دسکتاپ سبک، سریع و کاملاً محلی برای اجرای خودکار زنگ‌های مدرسه روی ویندوز ۱۰ و ۱۱.

> **Simple enough for a school employee, powerful enough to run the entire
> school bell schedule reliably.**

<div dir="rtl">

## معرفی

کاربر اصلی فقط شش کار می‌خواهد انجام دهد: برنامه زنگ‌ها را تعریف کند، ساعت‌ها را
ببیند، سیستم را فعال کند، زنگ‌ها خودکار پخش شوند، صدا را تست کند و در صورت نیاز
برنامه را تغییر دهد. کل رابط کاربری حول همین شش کار ساخته شده است.

## قابلیت‌ها

### صفحه اصلی (Dashboard)

- وضعیت لحظه‌ای سیستم: فعال / متوقف / غیرفعال
- ساعت بزرگ و تاریخ کامل شمسی + میلادی + روز هفته
- **زنگ بعدی** به همراه شمارش معکوس (`00:12:46`)
- چهار کنترل سریع: شروع · توقف · تست زنگ · غیرفعال‌سازی
- جدول «برنامه امروز» با وضعیت هر زنگ: پخش شد / بعدی / رد شد

### برنامه زنگ‌ها

- افزودن، ویرایش، حذف و تغییر ترتیب زنگ‌ها
- فعال یا غیرفعال کردن هر زنگ به‌صورت مستقل
- انتخاب ساعت، عنوان، یادداشت و فایل صوتی برای هر زنگ
- چند برنامه مستقل (مثلاً برنامه عادی و برنامه امتحانات) با انتخاب برنامه فعال
- انتخاب روزهای فعال هفته برای هر برنامه (شنبه تا جمعه)

### صدا

- صدای پیش‌فرض مدرسه (`resources/school-bell.mp3`) در اولین اجرا خودکار در
  پوشه صداهای برنامه نصب می‌شود و صدای همهٔ زنگ‌هاست
- **پخش خودکار روی ویندوز از پخش‌کننده خود ویندوز** (`MediaPlayer`) استفاده
  می‌کند، نه از صدای داخلی مرورگر. این تنها راه قابل اتکا برای زنگی است که
  باید سر وقت و بدون باز شدن هیچ پنجره‌ای پخش شود. اگر پخش بومی به هر دلیلی
  ممکن نباشد، به‌طور خودکار از پنجره پنهان داخلی استفاده می‌شود
- اگر پخش یک زنگ خودکار شکست بخورد، حداکثر ۳ بار با فاصله ۱۰ ثانیه تکرار
  می‌شود؛ اگر برنامه در حالت تری (پنهان) باشد، خطا به‌صورت اعلان ویندوز هم
  نشان داده می‌شود تا هیچ خرابی بی‌صدا نماند
- دکمهٔ «تست زنگ» روی صفحهٔ اصلی، صدای پیش‌فرض را پخش می‌کند

### گزارش فعالیت

هر تصمیم موتور زنگ — از جمله «چرا این زنگ پخش نشد» — در `activity-log.json`
داخل پوشهٔ دادهٔ برنامه ثبت می‌شود. این تنها سندی است که هنگام خرابی به
کار می‌آید، بنابراین نوشتن آن حذف نشده است؛ فقط صفحهٔ نمایش آن از رابط
کاربری برداشته شده و فایل را باید مستقیم باز کنید.

## زبان و راست‌چین

برنامه به‌طور کامل دو زبانه است و هیچ متنی در کد نوشته نشده است. هر ۱۵۵ کلید ترجمه
در `src/i18n/` نگهداری می‌شود و یک تست واحد تضمین می‌کند که هر دو زبان دقیقاً
کلیدهای یکسانی داشته باشند.

- **فارسی** — چینش راست‌به‌چین واقعی، فونت وزیرمتن (همراه برنامه)، تاریخ شمسی و
  ارقام فارسی
- **English** — چینش چپ‌به‌راست، ساعت ۱۲ ساعته، تاریخ میلادی

تغییر زبان بلافاصله اعمال می‌شود. جهت چیدمان با ویژگی‌های منطقی CSS
(`margin-inline-start` و …) نوشته شده است، بنابراین هر دو جهت از یک شیوه‌نامه
استفاده می‌کنند.

## موتور زمان‌بندی

دقت، مهم‌ترین ویژگی این برنامه است:

- یک تایمر دقیق برای **میلی‌ثانیه دقیق** زنگ بعدی تنظیم می‌شود (نه `setInterval`)
- در هر بیدار شدن، ساعت سیستم دوباره خوانده می‌شود؛ بنابراین تغییر ساعت، حالت
  خواب و بیداری (Sleep/Resume) و تغییر ساعت تابستانی خودکار مدیریت می‌شوند
- هر زنگ یک شناسه یکتا می‌گیرد، مثلاً `2026-09-27_09:30_b1`، و در فایل ذخیره می‌شود.
  به همین دلیل **یک زنگ هرگز دوبار پخش نمی‌شود**، حتی اگر برنامه چند بار
  بازمحاسبه شود یا ری‌استارت شود
- اگر برنامه دیرتر از حد مجاز باز شود، زنگ‌های از دست رفته طبق تنظیم کاربر
  «نادیده گرفته می‌شوند» یا «اگر اخیر باشند پخش می‌شوند»
- حداکثر ۱۵ دقیقه بعد از هر بیدار شدن، وضعیت دوباره بررسی می‌شود تا هیچ شرایطی
  از قلم نیفتد

## ذخیره‌سازی

همه چیز محلی است و چیزی به اینترنت ارسال نمی‌شود.

- مسیر داده: `%APPDATA%\DS School Bell` (ویندوز)
- `state.json` — برنامه‌ها، زنگ‌ها، صداها و تنظیمات
- `activity-log.json` — گزارش فعالیت (تنها سندِ «چرا زنگی پخش نشد»)
- `sounds/` — فایل‌های صوتی، شامل `school-bell.mp3` که در اولین اجرا نصب می‌شود
- **نوشتن اتمیک:** هر نوشتن ابتدا در فایل موقت انجام و سپس با `rename` جایگزین
  می‌شود. یک کپی `.bak` از آخرین نسخه سالم نگهداری می‌شود، بنابراین قطع برق یا
  بسته شدن ناگهانی هیچ تنظیمی را از بین نمی‌برد
- هر داده‌ای که از دیسک یا از فایل پشتیبان خوانده می‌شود، اعتبارسنجی می‌شود؛
  فایل خراب یا دستکاری‌شده هرگز باعث کرش نمی‌شود

## پشتیبان‌گیری

برای پشتیبان گرفتن کافی است کل پوشهٔ دادهٔ برنامه را کپی کنید. هر نوشتن اتمیک
است و یک کپی `.bak` هم نگه داشته می‌شود، بنابراین کپی سادهٔ پوشه همیشه سالم
می‌ماند.

## میان‌برهای صفحه‌کلید

| کلید       | کار         |
| ---------- | ----------- |
| `Space`    | شروع / توقف |
| `Ctrl + T` | تست زنگ     |
| `Esc`      | بستن پنجره  |

میان‌برها هنگام تایپ در فیلدها غیرفعال می‌شوند و `Space` روی دکمه‌ها به همان
شکل معمولی کار می‌کند.

## توسعه

### پیش‌نیازها

- Node.js ۲۰ یا بالاتر
- Python ۳ (فقط برای بازتولید آیکون و صدای پیش‌فرض)

### نصب

```bash
npm install
```

### اجرا در حالت توسعه

```bash
npm run dev
```

### تست‌ها

```bash
npm test          # ۸۲ تست واحد: زمان، تاریخ شمسی، موتور زنگ، پخش‌کننده بومی، اعتبارسنجی
npm run test:e2e  # تست انتها‌به‌انتها داخل Electron (۶۰ بررسی)
```

تست انتها‌به‌انتها موتور زمان‌بندی، پخش صدای واقعی، ذخیره‌سازی، پشتیبان‌گیری،
ترجمه‌ها و پنجره را اجرا می‌کند.

### بررسی کیفیت

```bash
npm run typecheck   # TypeScript در دو محیط (main و renderer)
npm run lint        # ESLint
npm run format      # Prettier
```

### گرفتن اسکرین‌شات از رابط کاربری

```bash
npm run capture     # نمای فارسی/انگلیسی، روشن/تاریک، در اندازه‌های مختلف
```

تصاویر در پوشه `screenshots/` ذخیره می‌شوند.

## ساخت نسخه نهایی

### ویندوز (Installer + Portable)

```bash
npm run build:win:all
```

خروجی‌ها در پوشه `release/`:

| فایل                          | توضیح                                        |
| ----------------------------- | -------------------------------------------- |
| `DS School Bell-Setup.exe`    | نصب‌کننده کامل با انتخاب پوشه نصب            |
| `DS School Bell-Portable.exe` | نسخه پورتابل، بدون نصب — روی فلش اجرا می‌شود |

برای ساخت فقط یکی از آن‌ها هم می‌شود `npm run build:win` یا `npm run build:win:portable` را اجرا کرد.

Installer با NSIS ساخته می‌شود و شامل موارد زیر است:

- انتخاب پوشه نصب
- ساخت میان‌بر در دسکتاپ و منوی Start
- ورودی «Start with Windows» در رجیستری ویندوز
- uninstaller که تنظیمات کاربر را **پاک نمی‌کند** (تا برنامه‌های مدرسه از بین نرود)

> **نکته:** ساخت Installer روی لینوکس/macOS به Wine نیاز دارد و در حال حاضر
> **توصیه نمی‌شود**: بسته‌ی Wine که `electron-builder` به‌صورت خودکار دانلود می‌کند
> (`toolsets.wine`) ناقص منتشر شده و فایل‌های PE داخلی Wine را ندارد، بنابراین
> هرگز بالا نمی‌آید. برای ساخت `Setup.exe` این پروژه را روی **ویندوز** اجرا کنید
> (روی ویندوز اصلاً Wine لازم نیست).
>
> نسخه‌ی **Portable** بدون Wine و روی لینوکس هم ساخته می‌شود:
> `npm run build:win:portable`

### لینوکس (AppImage)

```bash
npm run build:linux
```

## بازتولید فایل‌های ثابت

آیکون‌ها به‌صورت محلی تولید می‌شوند و نیازی به دانلود ندارند:

```bash
npm run assets
```

صدای پیش‌فرض زنگ یک **ضبط واقعی** است: `resources/school-bell.mp3`.
این فایل عمداً بازتولید نمی‌شود، چون اجرای این دستور نباید صدای زنگ مدرسه را
عوض کند. اسکریپت فقط یک `fallback-bell.wav` می‌سازد که در نبود MP3 استفاده
می‌شود.

## عیب‌یابی

اگر زنگی سر وقت پخش نشد، به این ترتیب بررسی کنید. **فایل `activity-log.json`**
در پوشهٔ دادهٔ برنامه مهم‌ترین منبع است، چون هر تصمیم موتور زنگ — از جمله
«چرا پخش نشد» — در آن ثبت می‌شود. صفحهٔ نمایش آن حذف شده، پس فایل را مستقیم
باز کنید.

| نشانه در گزارش فعالیت                   | معنی                                              | راه‌حل                                                                          |
| --------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------- |
| `Bell "…" played at …`                  | زنگ پخش شد و صدا باید شنیده شده باشد              | اگر صدایی نشنیدید، مطمئن شوید بلندگو به این رایانه وصل است و صدای ویندوز بالاست |
| `Bell "…" did not play (…) — attempt N` | پخش شکست خورد و برنامه در حال تلاش مجدد است       | متن داخل پرانتز علت را می‌گوید                                                  |
| `Could not play bell "…"`               | هر ۳ تلاش شکست خورد                               | همان متن خطا را بخوانید؛ معمولاً فایل صوتی خراب یا غیرقابل پخش است              |
| `Sound file for bell "…" not found`     | فایل صوتی روی دیسک نیست                           | پوشهٔ `sounds/` را بررسی کنید؛ `school-bell.mp3` باید در آن باشد                |
| `Bell "…" at … is muted — skipped`      | خود آن زنگ غیرفعال است                            | در صفحه برنامه زنگ‌ها آن را فعال کنید                                           |
| `Bell "…" at … was missed`              | زنگ گذشته و خارج از مهلت مجاز بود                 | سیاست فعلی روی «نادیده گرفتن» است؛ برای تغییر باید در `state.json` ویرایش شود   |
| `No bells scheduled for today`          | امروز روز فعال نیست یا برنامه‌ای برای امروز ندارد | «روزهای فعال هفته» را بررسی کنید                                                |
| `Bell system paused`                    | سیستم روی «متوقف» است                             | با دکمه «شروع» یا از منوی نوار وظیفه فعال کنید                                  |

نکته‌های مهم هنگام عیب‌یابی روی ویندوز:

- **پخش بومی به PowerShell نیاز دارد.** اگر با Group Policy محدود شده باشد، برنامه
  خودش تشخیص می‌دهد و به پنجره پنهان داخلی برمی‌گردد؛ نتیجه در گزارش فعالیت با
  عبارت `attempt` و جزئیات خطا مشخص است.
- **صدای ویندوز و بلندگو** باید روی دستگاهی باشد که برنامه روی آن اجرا می‌شود.
- برنامه باید در حال اجرا باشد. نصب‌کننده‌ی NSIS کلید اجرای خودکار را در
  رجیستری ویندوز می‌نویسد؛ نسخهٔ پورتابل این کار را نمی‌کند و باید دستی اجرا
  شود.
- اگر برنامه در پس‌زمینه بسته شده بود، زنگ‌های گذشته طبق سیاست
  «زنگ‌های از دست رفته» رفتار می‌کنند.

## معماری

```
src/
├── main/                  فرایند اصلی — تمام منطق کسب‌وکار
│   ├── audio/             موتور صوتی: پخش‌کننده بومی ویندوز + پروتکل اختصاصی
│   │                       + پنجره پنهان پخش (پشتیبان)
│   ├── scheduler/         موتور زنگ: تایمر دقیق، ثبت اجراها
│   ├── services/          تمام تغییرات وضعیت و عملیات سطح بالا
│   ├── storage/           ذخیره‌سازی اتمیک، کتابخانه صدا، پشتیبان
│   ├── system/            پوسته، اجرای خودکار، مدیریت خطا
│   ├── tray/              نوار وظیفه
│   └── window/            مدیریت پنجره
├── preload/               پل تایپ‌شده و امن بین main و renderer
├── renderer/              رابط کاربری React
│   ├── components/        اجزای UI و سیستم طراحی
│   ├── pages/             دو صفحه: داشبورد و برنامه زنگ‌ها
│   ├── layouts/           چیدمان و ناوبری
│   ├── hooks/             قلاب‌های React
│   └── styles/            توکن‌های طراحی و شیوه‌نامه‌ها
├── shared/                کد مشترک و بدون وابستگی به Electron
├── i18n/                  ۱۵۵ کلید ترجمه فارسی و انگلیسی
├── types/                 قراردادهای داده و IPC
└── utils/                 تاریخ شمسی، زمان، شناسه
```

**اصل جداسازی:** رابط کاربری هیچ منطق کسب‌وکاری ندارد. موتور زنگ در فرایند اصلی
اجرا می‌شود، بنابراین حتی اگر رابط کاربری بسته، کند یا در حال بازسازی باشد،
زنگ‌ها همچنان پخش می‌شوند.

## امنیت

- `contextIsolation` و `sandbox` برای هر دو پنجره
- فقط `contextBridge` در اختیار رابط کاربری قرار می‌گیرد
- پروتکل صوتی اختصاصی فقط سه مسیر را سرو می‌کند: پوشه صداهای برنامه، فایل‌هایی که
  کاربر خودش انتخاب کرده، و صدای پیش‌فرض همراه برنامه
- ناوبری و پنجره‌های بیرونی مسدود شده‌اند
- ورودی‌ها پیش از ذخیره اعتبارسنجی می‌شوند
- حذف فایل صوتی فقط برای فایل‌هایی انجام می‌شود که خود برنامه کپی کرده است؛
  فایل‌های بیرونی کاربر هرگز حذف نمی‌شوند
